## Step 1：一句话说清楚这个项目（2 分钟）

```
这是一个 Linux 系统监控程序。
它每分钟从 /proc 文件系统读取 CPU、内存、网络、中断数据，
通过 gRPC 发送到服务器，再在网页上展示。
```

**面试官听到的：** 这个候选人有 Linux 内核接口、RPC 通信、系统编程的实战经验。

## Step 3：理解数据是怎么流动的（5 分钟）

```
   Linux /proc 文件（内核数据）
          │
          ▼
   C++ 监控器读取（ReadFile 类）
          │
          ▼
   差分计算（用上一次数据减这一次）
          │
          ▼
   填进 Protobuf 消息（MonitorInfo）
          │
          ▼
   gRPC 客户端发送（SetMonitorInfo）
          │
          ▼
   gRPC 服务端接收并缓存（按主机名存）
          │
          ▼
   Web Dashboard 查询并展示（GetMonitorInfo）
```

**三句话描述：**

1. **采集**：从 Linux `/proc` 目录读取 CPU/内存/网络数据
2. **传输**：用 gRPC 把数据从客户端发到服务端
3. **展示**：服务端提供 Web 页面，浏览器打开就能看

## Step 4：记住 5 个监控器（5 分钟）

| # | 监控器类 | 读哪个文件 | 关注什么 | 要不要差分 |
|---|----------|-----------|---------|-----------|
| 1 | `CpuLoadMonitor` | `/proc/loadavg` | 1/3/15 分钟平均负载 | ❌ 直接读 |
| 2 | `CpuStatMonitor` | `/proc/stat` | 8 种 CPU 使用率 % | ✅ 要差分 |
| 3 | `MemMonitor` | `/proc/meminfo` | 19 项内存指标 | ❌ 直接读 |
| 4 | `NetMonitor` | `/proc/net/dev` | 每个网卡收发速率 | ✅ 要差分 |
| 5 | `CpuSoftIrqMonitor` | `/proc/softirqs` | 10 类软中断速率 | ✅ 要差分 |

**为什么有的要差分？** 因为 `/proc/stat`、`/proc/net/dev`、`/proc/softirqs` 里存的是**开机以来的累计值**，不是实时值。必须用"这次减上次"才能得到最近几秒的实际值。

**为什么不全部直接读？** 因为 Linux 只提供累计值，不提供百分比。CPU 使用率必须自己算。

## Step 5：理解 4 个核心设计（5 分钟）

### 5.1 策略模式（Strategy Pattern）

```
MonitorInter (抽象接口：UpdateOnce、Stop)
    ├── CpuLoadMonitor    ← 各自的 UpdateOnce 实现
    ├── CpuStatMonitor
    ├── MemMonitor
    ├── NetMonitor
    └── CpuSoftIrqMonitor
```

**好处：** 想加磁盘监控？新增一个 `DiskMonitor` 类就行，`main.cpp` 里加一行注册代码，其他代码不用动。

### 5.2 RAII（资源获取即初始化）

```cpp
ReadFile file("/proc/stat");  // 构造：打开文件
// ... 读写操作 ...
// 出了作用域 → 析构：自动关闭文件
// 即使中间抛异常，析构函数也会执行
```

**好处：** 永远不用担心"忘了关闭文件"，编译器保证析构函数一定被调用。

### 5.3 差分计算引擎

```cpp
// 第一次采样（t=0）
cpu_total_old = 100000;  // 保存到 unordered_map

// 第二次采样（t=3秒后）
cpu_total_new = 100300;
cpu_use_rate = (100300 - 100000) / 3 = 100 jiffies/s
百分比 = 100 / 300 * 100 = 33.3%
```

**关键：** `unordered_map<string, CpuStat>` 用来存上一次的数据，key 是 CPU 名字（"cpu0"）。

### 5.4 Protobuf + gRPC

- **Protobuf**：代替 JSON，二进制格式，更快更小，有 schema 检查
- **gRPC**：代替 HTTP REST，基于 HTTP/2，适合服务间通信
- **为什么不直接用 JSON + HTTP？** 监控数据高频发送，Protobuf 体积小 3-10 倍，gRPC 延迟低

## Step 6：记住 3 个 C++11 语法点（5 分钟）

### 6.1 智能指针

```cpp
// unique_ptr: 独占所有权，不能拷贝
std::unique_ptr<std::thread> thread_(new std::thread(...));

// shared_ptr: 共享所有权，有引用计数
std::vector<std::shared_ptr<MonitorInter>> runners_;
```

**面试说：** 本项目用 `unique_ptr` 管理线程，用 `shared_ptr` 管理监控器（因为 vector 需要拷贝存储）。

### 6.2 Lambda 表达式

```cpp
thread_ = std::unique_ptr<std::thread>(new std::thread([&]() {
    while (true) {
        // 采集数据
        // 发送数据
        std::this_thread::sleep_for(std::chrono::seconds(3));
    }
}));
```

**面试说：** `[&]` 表示捕获外部所有变量（按引用），可以直接用外层的 `runners_`、`rpc_client_`、`name`。

### 6.3 override 关键字

```cpp
void UpdateOnce(MonitorInfo* info) override;  // ← 这声明了是重写基类虚函数
```

**面试说：** 如果基类没有这个函数签名，编译器直接报错，防止手误（比如少写一个参数）。

背下来，面试时自然地说：

```
1️⃣ 我做了个 Linux 系统监控项目，用 C++11 写的。
   它从 /proc 文件系统里读 CPU、内存、网络等数据。

2️⃣ 因为 /proc 里很多是累计值，我做了差分计算来得到实时速率。
   用 unordered_map 保存上一次采样，每次 (new-old)/时间差。

3️⃣ 架构上用了策略模式，MonitorInter 是抽象接口，5 个监控器分别实现。
   新增监控指标只需加一个子类，不用改主循环代码。

4️⃣ 数据传输用 gRPC + Protobuf，比 JSON+HTTP 快 3-10 倍。
   客户端采完数据推给服务端，服务端缓存后供 Web Dashboard 查询。

5️⃣ 项目完整可运行，Docker 一键部署，采集间隔 3 秒，
   单次数据约 1KB，CPU 占用不到 2%。
```
